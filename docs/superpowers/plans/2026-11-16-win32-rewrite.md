# Win32 Rewrite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace egui and nokhwa in the Windows app with Win32 (GDI) and Media Foundation, with a camera stream setting, no UI-thread camera calls, and a detailed log.

**Architecture:** Platform-free modules (geometry, config, border, modes, capture state machine, log, stall detector) stay testable on Linux. A `win` module (cfg(windows)) holds the Media Foundation layer, the capture worker threads, and 2 Win32 windows (setup and PiP) that share 1 `App` state on the UI thread.

**Tech Stack:** Rust stable, `windows` 0.62 (Win32 + Media Foundation), `embed-manifest` 1.5 (build), serde/serde_json, directories, anyhow.

**Spec:** `docs/superpowers/specs/2026-11-16-win32-rewrite-design.md`

## Global Constraints

- No egui, no eframe, no nokhwa. Remove them from `rust/Cargo.toml`.
- `windows = "0.62"` features: `Win32_Foundation`, `Win32_Graphics_Gdi`, `Win32_UI_WindowsAndMessaging`, `Win32_UI_Controls`, `Win32_UI_HiDpi`, `Win32_UI_Input_KeyboardAndMouse`, `Win32_System_Com`, `Win32_System_LibraryLoader`, `Win32_Media_MediaFoundation`, `Win32_Media_KernelStreaming`.
- No camera call (Media Foundation) on the UI thread. Every wait has a limit: 5 s for device listing, stream listing, device activation, and the first frame; 500 ms for a capture thread stop.
- While a detached (stuck) worker thread is alive, do not start a second worker of the same kind; show "The camera does not respond. Restart the app." in place of a new start.
- The UI-thread `App` state is in a `thread_local! RefCell`. Never keep a borrow over a Win32 call that can dispatch messages (`TrackPopupMenu`, `SetWindowPos`, `ShowWindow`, `DestroyWindow`, `MoveWindow`, `SendMessage` to own windows). Take the data out, drop the borrow, then call.
- Config path `%APPDATA%\webcam-view-pip\config.json`, log `log.txt` next to it. Window geometry in physical pixels.
- Menu labels in order: "Select area", "Select camera", "Border" (submenu: "None", "White", "Green", "Red", "Blue", "Yellow"), "Exit". Border width 3 physical pixels.
- User-visible text in Simplified Technical English.
- Linux checks after each task: `cargo test`, `cargo check --target x86_64-pc-windows-gnu --all-targets`, `cargo clippy --target x86_64-pc-windows-gnu --all-targets -- -D warnings`, `cargo clippy --all-targets -- -D warnings`. All run in `rust/`.

## Review Focus

1. Device listing or device activation never returns (driver hang) → the camera screen shows "The camera does not respond." after 5 s; the window still moves and closes. (Task 2 tests the timeout logic with a fake slow job.)
2. The first stream is infrared or the camera has no preview stream → the default is the first color stream. (Task 1 tests `default_stream`.)
3. The saved `stream` index is not in the camera, or the saved symbolic link changed after a USB port change → the default stream, and the camera found by name. (Task 1 tests.)
4. The camera is unplugged while the PiP shows → "Camera not available. Trying again…", a retry every 3 s, and the image returns after replug. (Task 1 tests the state machine.)
5. Display scale 150 % and a saved position on a removed monitor → the PiP opens on screen with the saved physical size. (Task 4, checked by reading the code; `position_visible` is tested.)

  - `pub struct VideoMode { pub subtype: u32, pub width: u32, pub height: u32, pub fps_num: u32, pub fps_den: u32 }` with `fps(&self) -> u32` (rounded, 0 if den is 0) and `label(&self) -> String` = `"1920×1080 30 fps MJPG"` (subtype as FourCC text; non-printable FourCC → hex).

  - `pub struct StreamInfo { pub index: u32, pub kind: StreamKind, pub color: bool, pub modes: Vec<VideoMode> }`
  - `pub fn is_color_subtype(subtype: u32) -> bool` — false for FourCC `L8  `, `L16 `, `D16 ` (and the D3DFMT values 50, 81, 80), else true.
  - `pub fn rank_modes(modes: &[VideoMode]) -> Vec<usize>` — indexes best first: modes with width×height ≤ 1920×1080 sorted by (min(fps, 30), pixels, fps) descending; then larger modes by pixels ascending.
  - `pub fn default_stream(streams: &[StreamInfo], saved: Option<u32>) -> Option<u32>` — saved if listed and color; else first color Preview; else first color stream.
  - `pub fn stream_label(s: &StreamInfo) -> String` — `"Preview — <best mode label>"`, `"Capture — …"`, `"Stream 3 — …"` for Other.
- `capture_logic.rs`: `pub enum CapEvent { OpenFailed, FirstFrame, NoFirstFrame, Lost, RetryFailed }`, `pub enum CapAction { TryMode(usize), Running, GiveUp, RetryLater }`, `pub struct Fallback` with `new(mode_count: usize) -> Fallback`, `start(&mut self) -> CapAction` (= `TryMode(0)`), `on(&mut self, e: CapEvent) -> CapAction`. Rules: before the first frame, `OpenFailed`/`NoFirstFrame` → next `TryMode(i)` while i < min(3, mode_count), else `GiveUp`. `FirstFrame` → `Running` (the mode is kept). After running, `Lost` and `RetryFailed` → `RetryLater` (same mode, never `GiveUp`).
- `geometry.rs` additions: `pub enum Hit { Move, Resize }`, `hit_test(x: i32, y: i32, w: i32, h: i32, grip: i32) -> Hit` (Resize if x ≥ w−grip and y ≥ h−grip); `keep_aspect(w: i32, aspect: f32, min_w: i32, min_h: i32) -> (i32, i32)` (width drives height, both at least the minimum, aspect kept as well as possible); `crop_src(area: NormRect, w: u32, h: u32) -> (i32, i32, i32, i32)` (x, y, width, height in pixels, at least 1×1, inside the frame).
- `watchdog.rs`: `Stage` gets `Message = 8` (from_u8 too); a `pub static MESSAGE: AtomicU32` holds the current window message; `enter_message(msg: u32)`, `leave_message()`, and `set_modal(bool)` (a modal move, size, or menu loop counts as `Outside`). The stall line names the message number.
- `main.rs`: modules `border, config, geometry, log, modes, capture_logic, watchdog`, and `#[cfg(windows)] mod win;`. On non-Windows, `main` prints "webcam-view-pip runs only on Windows." and returns. On Windows it calls `win::run()` (Task 3); in this task `win/mod.rs` has `pub fn run() {}`.
- `build.rs`: for a Windows target, embed a manifest with Common Controls 6 and per-monitor-v2 DPI awareness (`embed_manifest::new_manifest("webcam-view-pip")` with `.dpi_awareness(PerMonitorV2)`).
- `release.yml` Windows job: add `cargo clippy --all-targets --locked -- -D warnings` before Test.

### Task 2: Media Foundation layer and capture workers

**Files:**
- Create: `rust/src/win/mod.rs` (module list), `rust/src/win/mf.rs`, `rust/src/win/capture.rs`, `rust/src/worker.rs` (platform-free)

**Interfaces:**
- Consumes: `VideoMode`, `StreamInfo`, `StreamKind`, `is_color_subtype`, `rank_modes`, `Fallback`/`CapEvent`/`CapAction`, `log!`, `CAPTURE_FRAMES`.
- Produces (`worker.rs`, platform-free, tested): `pub struct Job<T>`; `Job::spawn(name: &str, f: impl FnOnce() -> T + Send + 'static) -> Job<T>`; `fn poll(&self) -> Option<T>` (result once ready); `fn wait(&self, limit: Duration) -> Result<T, TimedOut>`; a global count of jobs still alive per name: `alive(name: &str) -> usize`.
- Produces (`win/mf.rs`):
  - `pub struct Device { pub name: String, pub id: String }`
  - `startup() -> anyhow::Result<()>` (`MFStartup`, 1 time, from the UI thread at start — this is not a camera call)
  - `list_devices() -> anyhow::Result<Vec<Device>>` (`MFEnumDeviceSources`, friendly name and `MF_DEVSOURCE_ATTRIBUTE_SOURCE_TYPE_VIDCAP_SYMBOLIC_LINK`; logs each device)
  - `open_source(id: &str) -> anyhow::Result<IMFMediaSource>` (`MFCreateDeviceSource` with the symbolic link)
  - `list_streams(source: &IMFMediaSource) -> anyhow::Result<Vec<StreamInfo>>` (presentation descriptor; video streams only; kind from `MF_DEVICESTREAM_STREAM_CATEGORY` against `PINNAME_VIDEO_PREVIEW`/`PINNAME_VIDEO_CAPTURE`, still streams (`PINNAME_VIDEO_STILL`) skipped; `color` false if all subtypes fail `is_color_subtype` or `MF_DEVICESTREAM_ATTRIBUTE_FRAMESOURCE_TYPES` is infrared or depth; logs each stream with all modes)
  - `pub struct Reader` with `open(source: &IMFMediaSource, stream: u32, mode: &VideoMode) -> anyhow::Result<Reader>`: Source Reader with `MF_SOURCE_READER_ENABLE_VIDEO_PROCESSING`; only `stream` selected; the matching native type set; output subtype `MFVideoFormat_RGB32`; size and stride read back from the current type (a negative `MF_MT_DEFAULT_STRIDE` means bottom-up). Logs the output type.
  - `Reader::read(&mut self) -> anyhow::Result<ReadResult>` where `pub enum ReadResult { Frame(Frame), Tick, Lost }` (flags `MF_SOURCE_READERF_ERROR` or `ENDOFSTREAM` → `Lost`; no sample → `Tick`).
  - `pub struct Frame { pub width: u32, pub height: u32, pub bgra: Vec<u8> }` — top-down, stride = width×4.
- Produces (`win/capture.rs`):
  - `pub const WM_APP_FRAME: u32 = WM_APP + 1`, `WM_APP_STATUS = WM_APP + 2`.
  - `pub enum Status { Starting, Running(String /*mode label*/), Failed(String), Lost(String), NotResponding }`
  - `pub struct Capture` with `start(device: Device, stream: u32, hwnd: HWND) -> Capture`, `latest(&self) -> Option<Arc<Frame>>` (also clears the "posted" flag), `status(&self) -> Status`, and `Drop` (stop flag, `IMFMediaSource::Shutdown` on the current source, wait ≤ 500 ms, then detach).
  - Thread body: `CoInitializeEx(COINIT_MULTITHREADED)`; for each try: `open_source`, `list_streams` (modes of `stream`), `rank_modes`, `Reader::open` with the ranked mode from `Fallback`; a first-frame timer: if no frame in 5 s, `Shutdown` the source (this ends a blocked `ReadSample`) → `NoFirstFrame`; each new try uses a new source. Frames: store in the slot, increment `CAPTURE_FRAMES`, `PostMessageW(WM_APP_FRAME)` only if the posted flag was clear. `Lost` → status `Lost`, wait 3 s, retry (`RetryLater`). `GiveUp` → status `Failed(text)`, post `WM_APP_STATUS`, end.
  - `Capture::start` returns a `Capture` with status `NotResponding` (and starts no thread) if `worker::alive("capture") > 0`.

### Task 3: UI thread, setup window, and drawing

**Files:**
- Create: `rust/src/win/app.rs`, `rust/src/win/setup.rs`, `rust/src/win/draw.rs`
- Modify: `rust/src/win/mod.rs` (`run()`)

**Interfaces:**
- Consumes: everything from Tasks 1–2.
- Produces:
  - `win::run()`: log the version and OS build, `mf::startup()`, register the 2 window classes, create the setup window (hidden), load the config, then: if a camera is saved, list devices with a `Job` (≤ 5 s); if the saved camera is found, start the capture with the saved or default stream and show the PiP (Task 4) — else show the setup window. Message loop with `GetMessageW`.
  - Every window procedure calls `watchdog::enter_message(msg)` at the start and `leave_message()` at the end; `WM_ENTERSIZEMOVE`/`WM_ENTERMENULOOP` call `set_modal(true)`, the `EXIT` messages `set_modal(false)`.
  - `app.rs`: `struct App` (config, devices, streams, selected device and stream, area, page, capture, hwnds) in `thread_local! static APP: RefCell<Option<App>>`, and `fn with_app<R>(f: impl FnOnce(&mut App) -> R) -> Option<R>` (uses `try_borrow_mut`; returns None if re-entered).
  - `draw.rs`: `paint_image(hdc, dest: RECT, frame: &Frame, src: (i32,i32,i32,i32))` with `SetStretchBltMode(HALFTONE)` + `StretchDIBits` (top-down `BITMAPINFOHEADER`, negative height); `letterbox(container: RECT, aspect: f32) -> RECT` (uses `fit_aspect`); `fill_black`, `border_rect(hdc, rect, rgb, px)`, `grip_mark(hdc, rect)`, `dim_outside(hdc, image: RECT, sel: RECT)`. All painting through a memory DC (no flicker); `WM_ERASEBKGND` returns 1.
  - `setup.rs` camera page: label "Select camera", a LISTBOX of devices, a label "Stream", a LISTBOX of streams (`stream_label`), a status label, button "Next". Device list and stream list come from `Job`s polled by a 100 ms `WM_TIMER`; while waiting, the status label shows "Reading cameras…" / "Reading streams…"; after 5 s without a result it shows "The camera does not respond." On a new device selection: list its streams (a `Job` that runs `open_source` + `list_streams` + `Shutdown`), preselect `default_stream(…, saved stream if same camera)`. "Next" is enabled only with a camera and a stream.
  - `setup.rs` area page: the live image (letterboxed) from a `Capture`, drag with the left button to select (`NormRect::from_drag` on points relative to the image rect), `dim_outside`, buttons "Back", "Full image", "Confirm", the hint "Drag on the image to select the area." and the status text (`Status`). "Confirm" saves the config (camera name and id, stream, area) and opens the PiP (Task 4 interface `pip::show`). A `Status::Failed` returns to the camera page with the text.
  - Fonts: the system message font (`SystemParametersInfoForDpi` `NONCLIENTMETRICSW`), sized for the window DPI; `WM_DPICHANGED` resizes the window to the suggested rect.
